## Why tooling matters

Writing code is only half the job. Knowing how to **test**, **debug**, **measure**, and **configure** your Node.js environment turns a working script into a maintainable, production-ready application.

Node 24 (the active LTS) ships a built-in test runner, type stripping for `.ts` files, a powerful inspector protocol, and `perf_hooks` for timing — meaning you can do a lot without installing anything.

## Node release lines in 2026

| Line | Status (Sep 2026) | Use it for |
|------|-------------------|-----------|
| Node 22 | Maintenance LTS (until Apr 2027) | Existing production apps — `require(esm)`, type stripping since 22.18 |
| **Node 24** | **Active LTS** (LTS since Oct 2025) | New production apps — this course targets it |
| Node 26 | Current (LTS from Oct 2026) | Trying Temporal, `Iterator.concat()`, Undici 8 |

Node 18 and 20 are end-of-life. When a lesson says "Node 22+", the feature exists on every supported line.

## Choosing what to install

Node's built-ins cover most basic needs. Here is a quick decision guide:

```bash
# Zero dependencies — use the built-in runner
node --test src/**/*.test.js

# TypeScript without a build step (Node 22.18+ / 24 — type stripping is on by default)
node src/app.ts

# Run a package.json script without npm (Node 22+)
node --run dev

# Faster HMR + watch mode
npx tsx watch src/app.ts

# Lint + format in one tool (zero config)
npx biome check --apply src/
```

<Callout title="Built-in first, then extend">
Start with `node:test`, `node --inspect`, and `perf_hooks`. Add third-party tools only when you hit a real limitation — not by default.
</Callout>
