## JavaScript คือภาษาของ Node.js

Node.js คือ runtime ที่รัน JavaScript นอก browser ทุกอย่างที่เขียนใน Node ตั้งแต่ HTTP server ง่ายๆ ไปจนถึง CLI tool ที่ซับซ้อน ล้วนเป็น JavaScript ดังนั้นการเข้าใจภาษาอย่างแน่นหนาจึงเป็นสิ่งจำเป็นก่อนที่จะลงลึกใน API ของ Node

โมดูลนี้ครอบคลุม JavaScript พื้นฐานที่นักพัฒนามักสะดุดมากที่สุดในระบบนิเวศ Node:

| บทเรียน | หัวข้อ |
|---------|--------|
| Types และ Coercion | Primitives vs objects, `typeof`, `==` vs `===`, truthy/falsy |
| Scope และ Closures | `var`/`let`/`const`, block scope, hoisting, lexical scope |
| `this` และ Context | Dynamic `this`, `call`/`apply`/`bind`, arrow functions |
| Modules | ESM `import`/`export` vs CommonJS `require`, ใช้เมื่อไหร่ |

JavaScript สมัยใหม่หมายถึง **ES2022 ขึ้นไป** ตลอดทั้งโมดูล — `const`/`let`, arrow functions, destructuring, `async`/`await`, optional chaining และ native ES modules โมดูลนี้ยึด Node 24 (LTS ตัวปัจจุบัน) และทุกอย่างรันบน Node 26 ได้เช่นกัน

## ฟีเจอร์ภาษาใหม่ ๆ ที่คุณจะได้เจอ

Node อัปเกรด V8 ทุก major release ภาษาจึงโตขึ้นเรื่อย ๆ:

- **Node 24** — `using` / `await using` สำหรับเคลียร์ resource อัตโนมัติ, `RegExp.escape()`, `Error.isError()`, `Float16Array`
- **Node 26** — API วันเวลา **Temporal** เปิดเป็นค่าเริ่มต้น พร้อม `Map.prototype.getOrInsert()` และ `Iterator.concat()`

```js
// @skip-verify Node 26-only (Temporal) + illustrative openConnection()

// Node 24: using — the resource is disposed when the block exits

  conn.query('SELECT 1');
}                                   // conn[Symbol.dispose]() runs here, even on throw
```

## Script mode: sloppy vs strict

JavaScript ทุกชิ้นรันอยู่ใน mode ใดมode หนึ่งจากสองแบบ ตัดสินโดย **วิธีที่ไฟล์ถูกโหลด** ไม่ใช่โดยสิ่งที่โค้ดทำ:

- **Sloppy mode** — ค่า default ดั้งเดิม `<script>` tag แบบคลาสสิกใน browser หรือไฟล์ `.js` ใน package ที่ไม่มี `"type": "module"` จะรัน sloppy เว้นแต่จะ opt out sloppy mode ให้อภัยความผิดพลาดที่ปกติจะเป็น bug: การ assign ให้ชื่อที่ไม่เคยถูกประกาศจะสร้างตัวแปร global ขึ้นมาเงียบๆ แทนที่จะ throw และการเรียกฟังก์ชันแบบธรรมดาจะตั้ง `this` เป็น global object แทนที่จะเป็น `undefined`
- **Strict mode** — เปลี่ยนความให้อภัยแบบเงียบๆ เหล่านั้นให้กลายเป็น error ที่ throw ออกมา คุณจะได้ strict mode สามทาง: เขียน `'use strict';` เป็น statement แรกสุดในสคริปต์หรือฟังก์ชัน, โหลดไฟล์เป็น **ES module** (`.mjs` หรือ `.js` ที่มี `"type": "module"` — strict เสมอ ไม่ต้องมี directive), หรือเขียนโค้ด **ภายใน `class` body** (class body เป็น strict เสมอแม้อยู่ในไฟล์ที่ปกติเป็น sloppy)

## Mental Model

ให้นึกภาพ sloppy mode เป็น JavaScript ที่รันพร้อม safety net ที่ผ่อนปรน: typo และการประกาศตัวแปรที่ขาดหายจะถูกดูดซับเงียบๆ แทนที่จะหยุดโปรแกรม Strict mode เอา net นั้นออก มันไม่ได้เพิ่มฟีเจอร์ใหม่ — มันเอา silent failure path ออก แล้วเปลี่ยนเป็น error ที่ throw ตรงบรรทัดที่ความผิดพลาดเกิดขึ้นจริง เพราะ ES module และ class เป็น strict โดยไม่มีเงื่อนไข และโค้ด Node.js ใหม่แทบทั้งหมดเขียนเป็น ES module คุณควร default ไปที่การ *สมมติ* ว่าเป็น strict mode และมอง sloppy mode เป็นข้อยกเว้นแบบ legacy ที่คุณอาจเจอบ้างในไฟล์ CommonJS เก่า

## Trade-offs

| Mode | Benefit | Cost |
|---|---|---|
| Sloppy (legacy default) | สคริปต์เก่ายังรันได้โดยไม่ต้องแก้ | typo กลายเป็นตัวแปร global ที่มองไม่เห็นแทนที่จะเป็น error; `this` ในการเรียกแบบธรรมดากลายเป็น global object แบบเงียบๆ |
| Strict (ESM, class, `'use strict'`) | ความผิดพลาดปรากฏทันทีเป็น `ReferenceError`/`TypeError` ตรงจุดที่เกิด bug | pattern เก่าบางตัว (`arguments` บางแบบ, `with`) ใช้ไม่ได้ — แทบไม่มีผลกับโค้ดสมัยใหม่ |

## Common Misconceptions

- **"`'use strict'` เป็นของเก่าจาก ES5 ที่ไม่มีใครต้องใช้แล้ว"** ยังต้องใช้อยู่ในไฟล์ CommonJS `.js`/`.cjs` ธรรมดาถ้าต้องการ strict guarantee ที่นั่น — แต่ได้มันมาฟรีๆ โดยไม่ต้องมี directive ใน ES module และ class ทุกตัว
- **"Strict mode เปลี่ยนสิ่งที่โค้ดคำนวณ"** มันไม่ได้เพิ่มหรือเปลี่ยน semantics ของ arithmetic หรือ object มันแค่เปลี่ยนความผิดพลาดที่เคยเงียบให้กลายเป็น error ที่ throw
- **"ถ้าไฟล์มี `"type": "module"` ใน `package.json` ก็ยังต้องใส่ `'use strict'` ไว้บนสุดอยู่ดี"** ไม่จำเป็น — directive นั้นซ้ำซ้อนตรงนั้น เพราะ ESM เป็น strict โดยไม่มีเงื่อนไขอยู่แล้ว
