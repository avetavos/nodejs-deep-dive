## this คืออะไร?

`this` เป็น keyword พิเศษที่อ้างถึง **execution context** — object ที่ถือเป็น receiver ของการเรียกฟังก์ชันปัจจุบัน ต่างจากภาษาส่วนใหญ่ `this` ใน JavaScript ไม่ถูก bind เมื่อนิยาม แต่ถูกกำหนด ณ **เวลาที่เรียก** โดยวิธีที่ฟังก์ชันถูก invoke

## this ในรูปแบบการเรียกต่างๆ

```js
// 1. Method call — this is the object before the dot
const user = {
  name: 'Alice',
  greet: function() {
    return 'Hi, I am ' + this.name;
  },
};
console.log(user.greet()); // 'Hi, I am Alice'

// 2. Plain function call — this is undefined (strict mode) or globalThis
function whoAmI() {
  return typeof this; // 'undefined' in strict mode
}

// 3. Constructor call — this is the newly created object
function Person(name) {
  this.name = name;
}
const p = new Person('Bob');
console.log(p.name); // 'Bob'
```

## การสูญเสีย this

ปัญหาที่พบบ่อยที่สุด: การแยก method ออกจาก object ทำให้ binding หาย

```js
const timer = {
  label: 'tick',
  start: function() {
    // After 0 ms, fn is called as a plain function — this.label is undefined
    setTimeout(function() {
      console.log(this.label); // undefined — 'this' is not timer
    }, 0);
  },
};
```

## call, apply และ bind

ทั้งสาม method นี้ให้คุณ **กำหนด `this` อย่างชัดเจน**

```js
function introduce(greeting, punctuation) {
  return greeting + ', I am ' + this.name + punctuation;
}

const obj = { name: 'Carol' };

// call — pass arguments individually
introduce.call(obj, 'Hello', '!');     // 'Hello, I am Carol!'

// apply — pass arguments as an array
introduce.apply(obj, ['Hey', '.']);    // 'Hey, I am Carol.'

// bind — returns a NEW function with this permanently bound
const boundIntroduce = introduce.bind(obj);
boundIntroduce('Hi', '?');            // 'Hi, I am Carol?'
```

export const callApplyBindCode = `// @browser
function introduce(greeting, punctuation) {
  return greeting + ', I am ' + this.name + punctuation;
}

const obj = { name: 'Carol' };

console.log('call:', introduce.call(obj, 'Hello', '!'));
console.log('apply:', introduce.apply(obj, ['Hey', '.']));

const boundIntroduce = introduce.bind(obj);
console.log('bind:', boundIntroduce('Hi', '?'));

// bind is permanent — a second .bind() or .call() cannot override it
const reboundIntroduce = boundIntroduce.bind({ name: 'Someone else' });
console.log('re-bind is ignored:', reboundIntroduce('Yo', '!'));
`;

## Arrow functions และ this

Arrow functions **ไม่มี `this` ของตัวเอง** แต่ inherit `this` จาก **lexical enclosing scope** — function หรือ module scope รอบนอกที่จุดที่เขียน

```js
const timer2 = {
  label: 'tick',
  start: function() {
    // Arrow function inherits 'this' from start() — which is timer2
    setTimeout(() => {
      console.log(this.label); // 'tick' — correctly bound
    }, 0);
  },
};
```

ทำให้ arrow functions เป็นตัวเลือกที่เหมาะสมสำหรับ callbacks ภายใน methods

`<script>` ธรรมดารันแบบ **sloppy mode** โดย default ซึ่งการเรียก `this` ที่ detached จะ fallback ไปที่ global object เงียบๆ แทนที่จะ throw — demo ด้านล่างเปิด **strict mode** อย่างชัดเจน เพื่อให้การเรียกแบบ detached fail เหมือนที่จะเกิดขึ้นจริงใน ES module หรือ class ซึ่งทั้งคู่เป็น strict mode โดยอัตโนมัติ

## Demo ที่รันได้

export const thisCode = `// @browser
'use strict';
const counter = {
  count: 0,
  // Regular function — 'this' is counter when called as counter.method()
  incrementRegular: function() {
    this.count += 1;
    return this.count;
  },
};

console.log('after increment:', counter.incrementRegular()); // 1
console.log('after increment:', counter.incrementRegular()); // 2

// Detach the method — 'this' is lost
const detached = counter.incrementRegular;
try {
  detached(); // TypeError in strict mode
} catch (e) {
  console.log('detached call error:', e.message);
}

// Fix with bind
const bound = counter.incrementRegular.bind(counter);
console.log('bound call:', bound()); // 3
`;

## ตาราง this แบบครบ

รูปแบบการเรียกหกแบบครอบคลุม `this` bug แทบทั้งหมดที่คุณจะเจอในโค้ดจริง:

| รูปแบบการเรียก | `this` คืออะไร | สูญเสีย binding ไหม? |
|---|---|---|
| `obj.method()` | `obj` — object ก่อนจุด | ไม่ |
| `const fn = obj.method; fn()` (detached) | `undefined` ใน strict mode (throw เมื่อเข้าถึง); global object ใน sloppy mode | **ใช่** |
| Arrow function ที่ nest อยู่ใน method | `this` เดียวกับที่อยู่ใน method รอบนอก — inherit มา ไม่ใช่ของตัวเอง | ไม่ |
| Class field arrow (`prop = () => { ... }`) | instance นั้นอย่างถาวร — bind ครั้งเดียวตอน construct | ไม่ |
| Regular function ที่ส่งให้ `setTimeout`/array callback | ไม่ใช่ object ที่คุณคาดไว้ — timer object หรือ `undefined` ไม่เคยเป็น object ที่มัน "อยู่บน" | **ใช่** |
| `fn.bind(obj)` / `.call(obj)` / `.apply(obj)` | `obj` อย่างชัดเจน บังคับไม่ว่าผลลัพธ์จะถูกเรียกทีหลังอย่างไร | ไม่ (นั่นคือจุดประสงค์) |

## Mental Model

ให้นึกภาพ `this` เป็นพารามิเตอร์พิเศษที่มองไม่เห็นซึ่ง JavaScript เติมให้ **ณ จุดที่เรียก** ไม่ใช่ ณ จุดที่นิยาม — เหมือน argument แรกที่ไม่มี label ที่ทุก regular function ได้รับมาแบบลับๆ `obj.method()` เติมมันด้วย `obj` `fn()` เปล่าๆ เติมด้วย `undefined` (strict) หรือ global object (sloppy) `fn.call(obj)`/`fn.apply(obj)`/`fn.bind(obj)` ให้คุณเติมมันเองได้ Arrow function คือข้อยกเว้นเดียว: มันไม่ได้รับพารามิเตอร์ที่มองไม่เห็นนี้เลย — arrow function อ่าน `this` ตามตัวอักษรจาก scope ที่มันถูกเขียนไว้ เหมือนตัวแปรอื่นๆ ที่มัน close over

## Trade-offs

| Choice | Benefit | Cost |
|---|---|---|
| Regular function เป็น method | ได้ `this` แบบ dynamic ของตัวเอง ใช้ซ้ำได้กับ receiver object ต่างกัน (`fn.call(otherObj)`) | สูญเสีย `this` ได้ง่ายเมื่อแยกฟังก์ชันออกมาหรือส่งเป็น callback |
| Arrow function เป็น callback | สูญเสีย `this` ไม่ได้ — เพราะไม่เคยเป็นของตัวเองตั้งแต่แรก | re-target ด้วย `call`/`apply`/`bind` ไม่ได้; ไม่เหมาะเป็น object method เอง |
| Class field arrow | Auto-bound ครั้งเดียว ปลอดภัยที่จะส่งเป็น event handler หรือ callback โดยตรง | สร้างฟังก์ชัน instance ใหม่ต่อ object instance หนึ่งตัว ไม่ได้แชร์บน prototype (ต้นทุน memory เล็กน้อยเมื่อมีหลาย instance) |
| `.bind(obj)` | ทำให้ `this` ที่ถูกต้องถาวรและ override ไม่ได้แม้จะโดนเผลอ | สร้าง function object ใหม่ทุกครั้งที่เรียก — หลีกเลี่ยงการเรียก `.bind()` ใน loop ที่ทำงานบ่อย |

## Common Misconceptions

- **"Arrow functions เป็นแค่ syntax สั้นกว่าของ regular functions"** มันเปลี่ยน semantics ด้วย: ไม่มี `this` ของตัวเอง, ไม่มี `arguments` ของตัวเอง และใช้เป็น constructor ไม่ได้ (`new arrowFn()` throw)
- **"ถ้าฟังก์ชันถูกนิยามใน object literal `this` จะอ้างถึง object นั้นเสมอ"** จริงเฉพาะฟังก์ชันที่เขียนด้วย `method() {}` หรือ `method: function() {}` shorthand *และ* ถูกเรียกเป็น `obj.method()` เท่านั้น ฟังก์ชันเดียวกันที่ถูกแยกออกมาแล้วเรียกเดี่ยวๆ จะสูญเสีย binding นั้นไปทั้งหมด
- **"`bind` รันฟังก์ชันทันที"** `fn.bind(obj)` คืนฟังก์ชันใหม่ทั้งหมดโดยไม่เรียก `fn` คุณยังต้อง invoke ผลลัพธ์เอง
- **"Arrow class field ไม่มีต้นทุนเทียบกับ prototype method"** มัน bind ครั้งเดียวต่อ instance ซึ่งเป็นสิ่งที่คุณต้องการสำหรับ callback พอดี — แต่มันหมายความว่า N instance สร้าง function object แยกกัน N ตัว ต่างจาก prototype method ที่แชร์กันทุก instance

## Reading AI-generated code

`this` bug ที่พบบ่อยที่สุดในโค้ดที่ AI สร้างคือการส่ง object method ตรงๆ เป็น callback — `setTimeout(obj.method, 1000)`, `array.map(obj.method)`, `emitter.on('event', obj.method)` — ทั้งหมดนี้แยก method ออกจาก `obj` ตรงจุดที่มันถูกส่งไป เหมือน detached-call bug แบบคลาสสิกทุกประการ เพียงแต่ห่างออกมาอีกหนึ่งชั้นจนไม่ชัดเจน
