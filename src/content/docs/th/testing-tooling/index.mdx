## ทำไม tooling ถึงสำคัญ

การเขียนโค้ดเป็นเพียงครึ่งหนึ่งของงาน การรู้วิธี**ทดสอบ** **ดีบัก** **วัดผล** และ**ตั้งค่า**สภาพแวดล้อม Node.js จะเปลี่ยนสคริปต์ที่ทำงานได้ให้กลายเป็นแอปพลิเคชันที่ดูแลรักษาง่ายและพร้อม production

Node 24 (LTS ตัวปัจจุบัน) มี test runner ในตัว, type stripping สำหรับไฟล์ `.ts`, inspector protocol ที่ทรงพลัง, และ `perf_hooks` สำหรับจับเวลา ซึ่งหมายความว่าคุณทำได้มากโดยไม่ต้องติดตั้งอะไรเพิ่มเติม

## สาย release ของ Node ในปี 2026

| สาย | สถานะ (ก.ย. 2026) | ใช้กับอะไร |
|-----|--------------------|-----------|
| Node 22 | Maintenance LTS (ถึง เม.ย. 2027) | แอป production ที่มีอยู่แล้ว — `require(esm)`, type stripping ตั้งแต่ 22.18 |
| **Node 24** | **Active LTS** (เป็น LTS ตั้งแต่ ต.ค. 2025) | แอป production ใหม่ — คอร์สนี้ยึดเวอร์ชันนี้ |
| Node 26 | Current (เป็น LTS ตั้งแต่ ต.ค. 2026) | ลอง Temporal, `Iterator.concat()`, Undici 8 |

Node 18 และ 20 หมดอายุ (end-of-life) แล้ว เมื่อบทเรียนบอกว่า "Node 22+" หมายถึงฟีเจอร์นั้นมีในทุกสายที่ยังรองรับ

## สิ่งที่โมดูลนี้ครอบคลุม

| บทเรียน | หัวข้อ |
|---------|--------|
| Built-in Test Runner | `node:test`, `node:assert`, `test()`, `describe`/`it`, `node --test` |
| การดีบัก | `node --inspect`, Chrome DevTools, breakpoints, เมธอดต่าง ๆ ของ `console` |
| ประสิทธิภาพ | `perf_hooks`, `performance.now()`, `PerformanceObserver`, การหลีกเลี่ยงการบล็อก |
| Ecosystem และ Toolchain | TypeScript runners, ESLint/Prettier/Biome, nodemon, env files |

## ภาพรวม toolchain

```
┌─────────────────────────────────────────────────┐
│  Your Node.js Project                           │
│                                                 │
│  Source code (.ts / .js / .mjs)                 │
│       │                                         │
│       ▼                                         │
│  Linter / Formatter  ──►  ESLint, Prettier,     │
│                            Biome                │
│       │                                         │
│       ▼                                         │
│  TypeScript runner   ──►  node file.ts (built-  │
│                            in type stripping);  │
│                            tsx for enum etc.    │
│       │                                         │
│       ▼                                         │
│  Test runner         ──►  node:test (built-in)  │
│                            or Vitest / Jest      │
│       │                                         │
│       ▼                                         │
│  Debugger            ──►  node --inspect +      │
│                            Chrome DevTools       │
│       │                                         │
│       ▼                                         │
│  Performance         ──►  perf_hooks,           │
│                            PerformanceObserver   │
└─────────────────────────────────────────────────┘
```

## เลือกใช้อะไรดี

Built-in ของ Node ครอบคลุมความต้องการพื้นฐานได้เกือบทั้งหมด นี่คือแนวทางการตัดสินใจเบื้องต้น:

```bash
# ไม่ต้องติดตั้ง dependency — ใช้ built-in runner
node --test src/**/*.test.js

# TypeScript โดยไม่ต้อง build (Node 22.18+ / 24 — type stripping เปิดเป็นค่าเริ่มต้น)
node src/app.ts

# รัน script ใน package.json โดยไม่ผ่าน npm (Node 22+)
node --run dev

# HMR + watch mode ที่เร็วกว่า
npx tsx watch src/app.ts

# Lint + format ในเครื่องมือเดียว (zero config)
npx biome check --apply src/
```

<Callout title="เริ่มจาก built-in ก่อน แล้วค่อยขยาย">
เริ่มต้นด้วย `node:test`, `node --inspect`, และ `perf_hooks` จากนั้นค่อยเพิ่มเครื่องมือจาก third-party เมื่อคุณพบข้อจำกัดจริง ๆ ไม่ใช่ติดตั้งไว้ก่อนโดยไม่จำเป็น
</Callout>
